A5.1 – Text or Binary?

Aim

To design donor information using a text file and blood stock information using a binary file.

1. Donor File – Text File

The donor details are stored in a text file using fprintf().

Example Structure

typedef struct {
    int donorID;
    char name[50];
    char bloodGroup[4];
    int age;
} Donor;

Writing Donor Details

FILE *fp = fopen("donors.txt", "w");

if (fp != NULL) {
    fprintf(fp, "%d,%s,%s,%d\n",
            donor.donorID,
            donor.name,
            donor.bloodGroup,
            donor.age);

    fclose(fp);
}

Example Text File

101,Sandhiya,O+,20
102,Arun,A+,25
103,Ravi,B+,30

Why Use a Text File?

- Easy to read and understand.
- Can be opened using a text editor.
- Easy to modify donor information.
- Suitable for storing donor records.

2. Stock File – Binary File

The blood stock information is stored in a binary file using fwrite().

Structure

typedef struct {
    char bloodGroup[4];
    int units;
} Stock;

Writing Stock Information

FILE *fp = fopen("stock.dat", "wb");

if (fp != NULL) {
    fwrite(&stock, sizeof(Stock), 1, fp);
    fclose(fp);
}

Why Use a Binary File?

- Stores fixed-size records efficiently.
- Requires less conversion than text storage.
- Supports direct access using fseek().
- Suitable for frequent stock updates.

4. Comparison

Text File| Binary File
Human-readable| Not directly human-readable
Uses fprintf()| Uses fwrite()
Easy to edit| Efficient for fixed-size records
Requires text conversion| Stores data in binary form
Suitable for donor details| Suitable for blood stock

5. Conclusion

A text file is selected for donor information because it is easy to read, understand and modify. A binary file is selected for blood stock because it stores fixed-size records efficiently and supports direct access for updating stock. Therefore, using both formats makes the blood bank system efficient and easy to maintain.
