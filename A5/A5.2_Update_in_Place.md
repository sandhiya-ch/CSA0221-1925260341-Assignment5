A5.2 – Update in Place

Aim

To update the units of one blood group in a binary stock file using fseek(), fread() and fwrite() without rewriting the entire file.

1. Stock Structure

typedef struct {
    char bloodGroup[4];
    int units;
} Stock;

2. Algorithmic Pseudocode

ALGORITHM UPDATESTOCK(filename, targetGroup, newUnits)

BEGIN
    OPEN filename in read and write binary mode

    IF file cannot be opened THEN
        DISPLAY "File opening failed"
        RETURN FAILURE
    ENDIF

    WHILE a complete record can be read using fread()
        IF current.bloodGroup = targetGroup THEN

            MOVE file position back by SIZEOF(Stock)
            USING fseek()

            current.units ← newUnits

            WRITE current record using fwrite()

            IF writing fails THEN
                DISPLAY "Update failed"
                CLOSE file
                RETURN FAILURE
            ENDIF

            CLOSE file
            RETURN SUCCESS
        ENDIF
    ENDWHILE

    DISPLAY "Blood group not found"
    CLOSE file
    RETURN FAILURE
END

3. Explanation of File Functions

Function| Purpose
fopen()| Opens the binary file.
fread()| Reads a stock record.
fseek()| Moves the file pointer to the required record.
fwrite()| Writes the updated record.
fclose()| Closes the file.

4. Example

Original Stock File

Blood Group| Units
A+| 20
B+| 15
O+| 10
AB+| 8

Suppose the O+ stock is updated from 10 to 25.

Updated Stock File

Blood Group| Units
A+| 20
B+| 15
O+| 25
AB+| 8

Only the required record is updated. The remaining records are unchanged.

5. Why Is Updating a Text File Difficult?

- Text records may have different lengths.
- Changing one value may change the line length.
- The remaining records may need to be shifted.
- Usually, the entire file must be rewritten safely.

Therefore, updating a particular record directly is easier with fixed-size binary records.

6. Alternative Concept – Rewriting the Entire Text File

Instead of updating the binary file directly, the program can:

1. Open the text file.
2. Read all donor stock records.
3. Find the required blood group.
4. Change its units.
5. Write all records into a temporary text file.
6. Replace the original file with the updated file.

Pseudocode

ALGORITHM UPDATE_TEXT_FILE(filename, targetGroup, newUnits)

BEGIN
    OPEN original file for reading
    OPEN temporary file for writing

    FOR EACH record in original file DO
        IF record.bloodGroup = targetGroup THEN
            record.units ← newUnits
        ENDIF

        WRITE record into temporary file
    ENDFOR

    CLOSE both files

    REPLACE original file with temporary file
END

7. Complexity Analysis

Let n be the number of stock records.

Method| Time Complexity per Update
Binary update in place| O(1) with direct record position
Text file rewrite| O(n)

Space Complexity:

- Binary update requires O(1) extra memory for one record.
- Text rewriting requires temporary file storage proportional to the file size.

8. File Size Comparison

Text File| Binary File
Stores readable characters.| Stores fixed-size records.
File size depends on character representation.| File size depends on structure size.
Easy to inspect manually.| Efficient for fixed-size records.

9. Conclusion

Binary files are suitable for stock records because fixed-size records can be updated using fseek(), fread() and fwrite(). Text files are easier to read but updating a record may require rewriting the entire file. Therefore, binary storage is recommended for frequent stock updates.
