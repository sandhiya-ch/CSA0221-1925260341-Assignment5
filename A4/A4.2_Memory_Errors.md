A4.2 – Memory Errors

Aim

To understand memory errors such as memory leaks, dangling pointers and double free in the District Blood Bank Network and explain how to prevent them.

1. Memory Leak

A memory leak occurs when dynamically allocated memory is not released using free() after it is no longer needed.

Example

Donor *donors = malloc(10 * sizeof(Donor));

donors = NULL;

Here, the allocated memory address is lost without calling free(). Therefore, the memory cannot be accessed or released.

Prevention

free(donors);
donors = NULL;

The allocated donor memory must be released when it is no longer required.

2. Dangling Pointer

A dangling pointer is a pointer that refers to memory that has already been released.

Example

Donor *donors = malloc(10 * sizeof(Donor));

free(donors);

/* donors is now a dangling pointer */

Using this pointer after freeing the memory may cause undefined behaviour.

Prevention

free(donors);
donors = NULL;

Setting the pointer to NULL prevents accidental use through that pointer.

3. Double Free

A double free occurs when the same allocated memory is released more than once.

Example

free(donors);
free(donors);

This may cause a program crash or undefined behaviour.

Prevention

free(donors);
donors = NULL;

if (donors != NULL) {
    free(donors);
    donors = NULL;
}

Setting the pointer to NULL after freeing helps prevent a second free through the same pointer.

4. Comparison of Memory Errors

Memory Error| Meaning| Prevention
Memory leak| Allocated memory is not released.| Use free() when finished.
Dangling pointer| Pointer refers to released memory.| Set pointer to NULL after free().
Double free| Same memory is freed twice.| Track ownership and clear pointers after freeing.

5. Application in the Blood Bank Program

- Memory leaks can occur if donor records are allocated but never released.
- Dangling pointers can occur if donor memory is freed but the pointer is still used.
- Double free can occur if the donor list is released twice.

The program should manage memory carefully, use free() correctly and set released pointers to NULL.

6. Alternative Concept – Fixed Increase of 10 Records

Instead of doubling the donor list capacity, the program can increase its capacity by 10 records whenever it becomes full.

Pseudocode

ALGORITHM ADDDONOR_FIXED(donors, count, capacity, newDonor)

BEGIN
    IF count = capacity THEN

        newCapacity ← capacity + 10

        temp ← REALLOCATE donors TO newCapacity

        IF temp = NULL THEN
            DISPLAY "Memory allocation failed"
            RETURN FAILURE
        ENDIF

        donors ← temp
        capacity ← newCapacity

    ENDIF

    donors[count] ← newDonor
    count ← count + 1

    RETURN SUCCESS
END

7. Complexity Analysis

Method| Total Copying Cost| Unused Capacity
Doubling capacity| O(n) overall| Less than approximately half the capacity
Increasing by 10| O(n²) overall| At most 9 unused records

Here, n represents the total number of donors.

8. Comparison

Doubling Strategy:

- Capacity doubles whenever the list becomes full.
- Requires fewer reallocations.
- Has O(n) total copying cost.
- May leave more unused memory.

Fixed Increase Strategy:

- Capacity increases by 10 records each time.
- Requires more reallocations.
- Has O(n²) total copying cost.
- Leaves at most 9 unused records.

9. Conclusion

Memory errors can affect the safety and reliability of the blood bank program. Memory leaks, dangling pointers and double free must be prevented through proper memory management. The doubling strategy is recommended because it reduces the total copying cost to O(n), making it suitable for a large donor list.
