B3.4 – Engineering Trade-Off

1. Text File vs Binary File

Text File| Binary File
Data is stored as readable characters.| Data is stored in binary form.
Easy to open and edit.| Not easily readable by humans.
Usually requires more space for numeric data.| Often uses less space for fixed-size records.
Updating one record may require rewriting the file.| A fixed-size record can be updated using "fseek()".
More portable between different computers.| Portability can be affected by data representation, byte order and structure padding.

3. Portability

Text files are more portable because they store readable characters. They can usually be opened on different computers and operating systems.

Binary files may not work identically on every computer because of differences in byte order, integer representation and structure padding.

4. Completed Code – TODO 1

#include <stdio.h>

typedef struct {
    int group_code;
    int units;
} Stock;

int update_units(FILE *fp, int index, int units)
{
    Stock s;

    if (fp == NULL || index < 0)
        return 0;

    if (fseek(fp, (long)index * sizeof(Stock), SEEK_SET) != 0)
        return 0;

    if (fread(&s, sizeof(Stock), 1, fp) != 1)
        return 0;

    s.units = units;

    if (fseek(fp, -(long)sizeof(Stock), SEEK_CUR) != 0)
        return 0;

    if (fwrite(&s, sizeof(Stock), 1, fp) != 1)
        return 0;

    return 1;
}

int main(void)
{
    FILE *fp = tmpfile();

    if (fp == NULL) {
        perror("tmpfile");
        return 1;
    }

    Stock initial[5] = {
        {1, 40}, {2, 25}, {3, 12}, {4, 8}, {5, 30}
    };

    fwrite(initial, sizeof(Stock), 5, fp);

    printf("update record 3: %s\n",
           update_units(fp, 3, 20) ? "done" : "failed");

    printf("update record 9: %s\n",
           update_units(fp, 9, 20) ? "done" : "failed");

    rewind(fp);

    Stock s;

    while (fread(&s, sizeof s, 1, fp) == 1)
        printf("%d:%d ", s.group_code, s.units);

    printf("\n");

    fclose(fp);
    return 0;
}

5. Expected Output

update record 3: done
update record 9: failed
1:40 2:25 3:12 4:20 5:30

Explanation: The program uses zero-based indexing, so index 3 updates the fourth record. Index 9 is outside the five-record file. The read fails, so the program does not write anything and the file remains unchanged.

6. Alternative Concept – One fwrite Call

Instead of writing each stock record separately, the entire array can be written using one "fwrite()" call.

fwrite(stock, sizeof(Stock), n, fp);

- Number of library calls: one write call for the array.
- Time complexity: O(n), because all n records must be written.
- Memory required: O(n), because the complete array must be held in memory.
- Writing records individually also takes O(n) total time, but uses n write calls.

7. Final Recommendation

- Text format: Recommended for donor records because the information is readable, easy to inspect and more portable.
- Binary format: Recommended for fixed-size blood stock records because they can be accessed and updated directly using "fseek()".

The best format depends on whether readability and portability or fast direct access is more important.
