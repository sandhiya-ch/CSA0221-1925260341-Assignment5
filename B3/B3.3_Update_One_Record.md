B3.3 – Update One Record

1. Objective

To measure the time required to update the 50,000th donor record in a binary file and a text file.

2. Binary File Update

1. Open the binary file using "rb+" mode.
2. Use "fseek()" to move directly to the 50,000th record.
3. Use "fread()" to read the record.
4. Change the required donor information.
5. Use "fseek()" to return to the same record.
6. Use "fwrite()" to save the updated record.
7. Measure the time taken.

3. Text File Update

1. Open the original text file for reading.
2. Read all donor records.
3. Copy the records into a temporary file.
4. Change the 50,000th donor record while writing.
5. Complete writing the remaining records.
6. Replace the original file with the updated temporary file.
7. Measure the time taken.

4. Observation Table

File Format| Record Updated| Time Taken
Binary file| 50,000th donor| To measure
Text file| 50,000th donor| To measure

5. Analysis

- Binary files allow direct access to fixed-size records using "fseek()".
- Text files generally require reading and rewriting the records to update one record safely.
- Updating a binary record directly avoids rewriting the entire file.
- The actual execution time must be measured on the computer.

6. Complexity Analysis

Method| Time Complexity
Binary in-place update at a known record index| O(1)
Text file rewrite| O(n)

7. Result

The experiment compares the time required to update one donor record in binary and text formats. Binary files support direct updates for fixed-size records, while text files generally require rewriting the file.
