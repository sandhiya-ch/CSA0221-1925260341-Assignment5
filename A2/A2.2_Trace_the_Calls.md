A2.2 – Trace the Calls

Aim

To trace the recursive calls of the digital root and power functions and understand how the call stack works.

2. Power Function – Linear Recursion

Input: base = 2, n = 5

Formula

2⁵ = 2 × 2 × 2 × 2 × 2 = 32

Recursive Pseudocode

ALGORITHM POWER_LINEAR(base, n)

BEGIN
    IF n = 0 THEN
        RETURN 1
    ENDIF

    RETURN base × POWER_LINEAR(base, n - 1)
END

3. Power Function – Halving Recursion

Input: base = 2, n = 5

Formula

2⁵ = 32

Function Call Trace

POWER(2,5)
     |
POWER(2,2)
     |
POWER(2,1)
     |
POWER(2,0)
     |
    1

The exponent is divided by 2 at every recursive call.

Call Stack at Deepest Point

| POWER(2,0) |
| POWER(2,1) |
| POWER(2,2) |
| POWER(2,5) |

Result = 32

4. Recurrence for Number of Calls

Linear Power Recursion

C(n) = C(n - 1) + 1

Base case:

C(0) = 1

Time Complexity: O(n)

Space Complexity: O(n)

Halving Power Recursion

C(n) = C(floor(n / 2)) + 1

Base case:

C(0) = 1

Time Complexity: O(log n)

Space Complexity: O(log n)

5. Comparison

Linear Recursion| Halving Recursion
Reduces exponent by 1.| Divides exponent by 2.
More function calls.| Fewer function calls.
O(n) time.| O(log n) time.
O(n) stack space.| O(log n) stack space.
Slower for large n.| Faster for large n.

6. Conclusion

The call stack stores function calls until the base case is reached. Linear recursion makes more calls because it reduces the exponent by one. Halving recursion reduces the exponent by half, making it faster and more memory-efficient for large values of n.
